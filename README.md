# F-rum-Bot

**F-rum-Bot** — Telegram-бот для модерации групп сообщества **VISE RUSSIA**, интеграции с форумом на XenForo и управления ролями участников. Проект построен на Python, aiogram и PostgreSQL.

Бот объединяет инструменты модерации Telegram-групп, проверку форумных профилей и наказаний, обработку жалоб, систему должностей команды и локальные роли каждой группы. Отдельный отдел контроля качества управляет тестами и проверяет результаты кандидатов; полномочия на создание тестов и просмотр результатов разделены.

> **Статус разработки:** основные функции модерации, локальные роли и тестирование находятся в `main`. Поддержка, публичный сайт и закрытая админ-панель развиваются совместно с Telegram-ботом. Статус отдельных функций следует проверять по `CHANGELOG.md` и объединённым PR.

## Возможности

### Модерация Telegram-групп
- Подключение группы к боту и индивидуальные настройки модерации.
- Антифлуд и фильтрация ссылок.
- Предупреждения, просмотр и сброс предупреждений.
- Временные ограничения, снятие ограничений, блокировка, разблокировка и исключение участников.
- Очистка сообщений, журнал и статистика модерации.
- Жалобы участников и очередь обработки жалоб.
- Чёрный список и локальные никнеймы участников.

### Интеграция с XenForo
- Получение профиля пользователя форума.
- Проверка статуса наказания.
- Ссылка на профиль форума.
- Получение статистики форума.

### Системные должности команды
Глобальные должности определяют доступ к функциям персонала, модерации, жалобам, настройкам, технической диагностике и поддержке. Назначение и снятие должностей проверяется по иерархии и записывается в журнал.

### Локальные роли групп
- Отдельная иерархия ролей для каждой Telegram-группы.
- Системные и пользовательские роли с числовыми приоритетами.
- Проверка полномочий при назначении и снятии ролей.
- Иммунитет от обычных модераторских действий.
- Настраиваемые минимальные приоритеты команд.
- Аудит изменений ролей и настроек.

### Telegram-тестирование
- Создание тестов, добавление вопросов и выдача персональных ссылок.
- Прохождение тестов в личном чате с ботом.
- Проверка ответов, проходного процента и периода повторной попытки.
- Возможность автоматически выдать выбранную локальную роль с приоритетом 1–79 после успешной сдачи.
- Защита от автоматической выдачи привилегированных ролей и от повышения участника выше его текущего уровня.

## Настройка

1. Склонируйте репозиторий:

   ```bash
   git clone https://github.com/Mark2312-eng/F-rum-Bot.git
   cd F-rum-Bot
   ```

2. Создайте виртуальное окружение и установите зависимости:

   ```bash
   python -m venv .venv
   source .venv/bin/activate
   # Windows: .venv\\Scripts\\activate
   pip install -r requirements.txt
   ```

3. Создайте файл `.env` на основе [`.env.example`](.env.example):

   ```env
   TELEGRAM_BOT_TOKEN=
   XF_API_KEY=
   XF_URL=https://your-forum.example
   OWNER_TELEGRAM_ID=
   DATABASE_URL=postgresql://user:password@localhost:5432/forum_bot
   ```

   Не публикуйте файл `.env`, токены или API-ключи.

4. Запустите бота:

   ```bash
   python main.py
   ```

При запуске приложение подключается к PostgreSQL, инициализирует необходимые таблицы, записывает базовую версию существующей схемы в `schema_migrations`, поднимает HTTP-сервер на порту из переменной `PORT` (по умолчанию `10000`) и запускает Telegram polling. Для защиты от параллельного получения обновлений polling использует PostgreSQL advisory lock. Таблица `schema_migrations` пока фиксирует исходную схему; перенос всех исторических SQL-операций в отдельные миграционные файлы выполняется поэтапно.

## Безопасность и ограничения

- Системная должность в базе бота сама по себе не выдаёт Telegram-права администратора.
- Для выполнения банов, мутов и других действий бот должен иметь соответствующие права в Telegram-группе.
- Telegram-бот не может первым написать пользователю в личные сообщения. Пользователь должен самостоятельно открыть чат с ботом и нажать `/start`; в системе тестирования для этого используется deep-link.
- Не храните токены и ключи в репозитории.
- Новые таблицы PR #35 добавляются миграциями; совместимость с текущим asyncpg-слоем сохранена.

## Конфиденциальность и рассылки

- При первом запуске в личном чате бот запрашивает подтверждение ознакомления с документами конфиденциальности и обработки данных.

## VIP за Telegram Stars

В боте доступен интерактивный VIP-магазин с карточками тарифов, отдельными экранами привилегий, сравнением уровней, разделами «Мой VIP» и «Помощь», а также подтверждением перед выставлением счёта. Доступны VIP Silver (25 ⭐), VIP Gold (50 ⭐) и VIP Diamond (100 ⭐). Каждая покупка действует 30 дней и **не продлевается автоматически**. Повторная оплата возможна только по новому действию пользователя.

Цены не зашиты в код: главный экран, карточки, сравнение и оплата используют одни и те же переменные окружения. Если цена не настроена, тариф помечается как временно недоступный, а покупка отключается:

- `VIP_SILVER_PRICE_STARS`
- `VIP_GOLD_PRICE_STARS`
- `VIP_DIAMOND_PRICE_STARS`

Каждое значение — целое число от 1 до 10 000. Эти переменные нужно задать в Render для backend-сервиса после проверки цен и правил проекта. Не добавляйте их в репозиторий.

Команды:

- `/vip` — магазин и покупка;
- `/vipstatus` — текущий уровень и срок действия;
- `/vipperks` — описание возможностей;
- `/vipprofile` — карточка участника;
- `/vipbadge` — текущий VIP-бейдж;
- `/vipname ТЕКСТ` — имя в карточке (Gold и Diamond);
- `/viptitle ТЕКСТ` — титул в карточке (только Diamond);
- `/paysupport` — информация по вопросам оплаты.

Платёж подтверждается через Telegram Stars Pre-Checkout и Successful Payment. В базе сохраняются счёт, уникальный Telegram charge ID и срок действия. Повторное получение одного и того же платежного события не продлевает срок повторно. Просроченные привилегии перестают действовать при проверке доступа.

VIP не даёт прав модератора, администратора или владельца и не меняет иерархию ролей. Профильные поля VIP используются только в карточке бота. Перед включением платных покупок владелец должен проверить цены, условия поддержки и возвратов; несовершеннолетним пользователям нужна предварительная разрешённая родителем или опекуном покупка.


## Мероприятия и голосования

- `/eventcreate Название | 2026-12-01T18:00+03:00 | Описание` — создать мероприятие (владелец проекта).
- `/events` — показать будущие мероприятия и записаться/отменить запись кнопками.
- `/pollcreate Вопрос | Вариант 1 | Вариант 2` — создать голосование (владелец проекта; до 6 вариантов).
- `/polls` — показать голосования и результаты. Участник может изменить свой голос.

Дата мероприятия должна содержать часовой пояс. Записи и голоса хранятся в PostgreSQL.


## Полный каталог должностей команды

Системные должности сгруппированы по направлениям. Владелец проекта определяется через `OWNER_TELEGRAM_ID` и не назначается обычной командой. Остальные должности хранятся в едином каталоге `staff_role_catalog.py`.

- Руководство проекта: команда проекта.
- Администрация и модерация: специальные администраторы, руководители администрации, администраторы, модераторы и лидер.
- Технический отдел: главный технический специалист, заместители и кураторы технического направления.
- Контроль качества: руководство тестированием, специалисты контроля качества и тестировщики.
- Discord, организации и поддержка: отдельные направления с собственными полномочиями.
- Зарегистрированный пользователь: базовая системная отметка без административных прав.

Полномочия разделены по областям: `moderation`, `technical`, `testing_review`, `organizations`, `support`, `discord_moderation`, `settings`, `staff_view`, `staff_manage`. Технические, тестовые, организационные и поддерживающие должности не получают права модерации автоматически. Старые ключи должностей сохраняются для совместимости с уже назначенными сотрудниками.


### Управление глобальной командой в панели

В закрытом разделе «Системная команда» владелец может назначать и снимать должности из полного каталога по Telegram ID. Сервер повторно проверяет сессию владельца, допустимость должности и иерархию через атомарные методы базы данных. Равные и старшие должности, владелец и собственная учётная запись защищены. Каталог группируется по отделам; полномочия каждой должности показаны в подсказке.


## Конкурсы и награды сообщества

- В группе владелец создаёт бесплатный конкурс: `/contestcreate Название | 2026-12-20T18:00+03:00 | 3 | Описание приза`.
- Участники смотрят конкурсы через `/contests` и записываются кнопкой под публикацией.
- После указанного срока владелец выполняет `/contestdraw ID`; победители выбираются случайно, результат сохраняется. Фактическую выдачу приза владелец подтверждает отдельно.
- Промокод создаётся командой `/promocreate КОД БАЛЛЫ ЛИМИТ`, активируется командой `/promo КОД`.
- `/daily` выдаёт ежедневные баллы, `/points` показывает баланс, `/leaderboard` — рейтинг, `/achievements` — достижения.
- Баллы — внутренняя система активности без денежной стоимости и обмена на Stars. Участие в конкурсах бесплатное.
